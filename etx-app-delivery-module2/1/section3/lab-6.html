Lab 6: Configure Automatic Instrumentation

In this lab, you’ll configure automatic instrumentation for Java applications using the Red Hat Build of OpenTelemetry Operator.

Automatic instrumentation enables applications to generate distributed traces without requiring any changes to the application source code. Instead, the OpenTelemetry Operator automatically injects a Java agent into the application when it is deployed.

By the end of this lab, you will have:

  • Created an OpenTelemetry Instrumentation resource

  • Configured automatic instrumentation for Java applications

  • Verified that telemetry data can be exported to the OpenTelemetry Collector

Configure Automatic Instrumentation

The OpenTelemetry Operator uses an Instrumentation custom resource to define how applications should collect and export telemetry data.

In this training, you’ll create an Instrumentation resource that configures Java applications to send traces to the OpenTelemetry Collector deployed in the previous lab.

Apply the following manifest.

oc apply -f - <<'EOF'
apiVersion: opentelemetry.io/v1alpha1
kind: Instrumentation
metadata:
  name: java-instrumentation
  namespace: etx-app-dev
  annotations:
    instrumentation.opentelemetry.io/inject-java: "true"
spec:
  exporter:
    endpoint: http://otel-collector-collector:4317
  propagators:
    - tracecontext
    - baggage
  sampler:
    type: always_on
  java:
    image: ghcr.io/open-telemetry/opentelemetry-operator/autoinstrumentation-java:latest
EOF

The annotation instrumentation.opentelemetry.io/inject-java: "true" enables automatic instrumentation for Java applications.

When an application is deployed with the corresponding instrumentation annotation, the OpenTelemetry Operator automatically injects the Java agent into the application container.

The always_on sampler captures every trace generated by the application, making it ideal for training and development environments. Production environments typically use sampling strategies to reduce telemetry volume.

Verify Automatic Instrumentation

Verify that the OpenTelemetry Collector is ready to receive telemetry data from instrumented applications.

View the collector logs.

oc logs deployment/otel-collector-collector \
  -n etx-app-dev

Initially, the collector logs may not contain any trace data because no instrumented applications have been deployed yet.

In a later lab, you’ll deploy the ETX App Base application with automatic instrumentation enabled. As the application generates requests, you’ll see distributed traces appear in the collector logs, confirming that telemetry is being collected successfully.
