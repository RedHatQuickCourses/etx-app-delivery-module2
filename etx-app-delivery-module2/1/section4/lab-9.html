Lab 9: Configure GitLab Integration and Shared Secrets

In this lab, you’ll integrate Red Hat Dev Spaces with GitLab using OAuth and configure shared secrets that are automatically available to developer workspaces.

GitLab integration enables developers to clone, pull, and push repositories without manually configuring Git credentials. You’ll also configure shared workspace secrets that can be used to provide common configuration, API keys, and service credentials to every workspace.

By the end of this lab, you will have:

  • Configured GitLab OAuth integration for Red Hat Dev Spaces

  • Registered GitLab as a source code management provider

  • Created shared secrets for developer workspaces

Configure GitLab OAuth Integration

Red Hat Dev Spaces integrates with GitLab using OAuth. Once configured, users authenticate with their GitLab account and can access repositories directly from their workspaces.

Create a GitLab OAuth Application

Create an OAuth application in GitLab that Red Hat Dev Spaces will use for authentication.

  1. Execute below command in Openshift cluster to retrieve the openshift cluster ingress domain route from your OpenShift cluster and store it in a variable for use in next steps.

    OPENSHIFT_CLUSTER_INGRESS_DOMAIN=$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
echo ${OPENSHIFT_CLUSTER_INGRESS_DOMAIN}

  2. Navigate to the GitLab URL provided on your RHDP lab information page.

  3. Sign-in using ETX SSO using credentials username: platform-developer / password: openshift if you have not logged in yet. After successful authentication, you’ll be redirected back to GitLab.

  4. Click your avatar in the upper-right corner and select Edit Profile.

  5. Navigate to Access  Applications.

  6. Click Add new application.

  7. Configure the application using the following settings, make sure to substitute the value for OPENSHIFT_CLUSTER_INGRESS_DOMAIN with the value your retrived in first step.

    Name

    devspaces

    Redirect URI

    https://devspaces.OPENSHIFT_CLUSTER_INGRESS_DOMAIN/api/oauth/callback

    Confidential

    Enabled

    Scopes

    api, write_repository, openid

  8. Click Save application.

  9. Record the Application ID and Secret. You’ll use these values in the next step.

Configure GitLab Authentication

Replace GITLAB_APPLICATION_ID and GITLAB_APPLICATION_SECRET with the values generated by GitLab before running the following commands.

GITLAB_APPLICATION_ID=<add-your-value-here>
GITLAB_APPLICATION_SECRET=<add-your-value-here>

Create a Kubernetes Secret that stores the GitLab OAuth credentials. Red Hat Dev Spaces automatically discovers this secret based on its labels and annotations.

GITLAB_URL="https://$(oc get route -n gitlab -l app=webservice -o jsonpath='{.items[0].spec.host}')"
echo "Using GitLab URL: $GITLAB_URL"

oc create secret generic gitlab-oauth-config \
  -n openshift-devspaces \
  --from-literal=id="$GITLAB_APPLICATION_ID" \
  --from-literal=secret="$GITLAB_APPLICATION_SECRET"

oc annotate secret gitlab-oauth-config \
  -n openshift-devspaces \
  che.eclipse.org/oauth-scm-server=gitlab \
  che.eclipse.org/scm-server-endpoint="$GITLAB_URL"

oc label secret gitlab-oauth-config \
  -n openshift-devspaces \
  app.kubernetes.io/part-of=che.eclipse.org \
  app.kubernetes.io/component=oauth-scm-configuration

echo "GitLab OAuth secret created successfully"

Next, register GitLab with the Dev Spaces CheCluster.

GITLAB_URL="https://$(oc get route -n gitlab -l app=webservice -o jsonpath='{.items[0].spec.host}')"

echo "Registering GitLab URL: $GITLAB_URL"

oc patch checluster devspaces -n openshift-devspaces \
  --type='merge' \
  -p "{\"spec\":{\"gitServices\":{\"gitlab\":[{\"secretName\":\"gitlab-oauth-config\",\"endpoint\":\"$GITLAB_URL\"}]}}}"
After GitLab is registered, users are prompted to authorize Dev Spaces the first time they open a workspace that references a GitLab repository. Once authorized, Git operations such as clone, pull, and push use the user’s GitLab identity automatically.

Configure Shared Workspace Secrets

Red Hat Openshift Dev Spaces can automatically mount Kubernetes Secrets and ConfigMaps into every workspace. This allows administrators to provide shared configuration, credentials, or API keys without requiring developers to configure them manually.

Secrets can be injected in one of the following ways:

  • Environment variables (mount-as: env)

  • Files (mount-as: file)

  • Individual files using subpaths (mount-as: subpath)

Configure AI Coding Assistant Credentials

Configures shared credentials for an AI coding assistant such as Continue, Roo, or Cline. Begin by obtaining an API key from the Red Hat Demo Platform MaaS.

  1. Open the Red Hat Demo Platform MaaS portal in your browser.

    Figure 2. RHDP MaaS Login page(Click the image to view it in full size in a new browser tab)

  2. Sign in using your Red Hat Demo Platform [RHDP] credentials.

  3. Select Model option.

    Figure 3. RHDP MaaS home page(Click the image to view it in full size in a new browser tab)

  4. Search for qwen3-14b model and select it.

    Figure 4. Model search result(Click the image to view it in full size in a new browser tab)

  5. Subscribe to the model.

    Figure 5. Subscribe the model(Click the image to view it in full size in a new browser tab)

  6. Navigate back to RHDP MaaS home page and select API Keys.

    Figure 6. RHDP MaaS home page(Click the image to view it in full size in a new browser tab)

  7. Create a new API key or select an existing one.

    Figure 7. Create API key(Click the image to view it in full size in a new browser tab)

  8. Copy the generated API key.

  9. Create the shared secret.

    Replace REPLACE_API_KEY with your MaaS API key before running the command. 
    oc create secret generic continue-llm-credentials \
  -n openshift-devspaces \
  --from-literal=LLM_API_KEY="REPLACE_API_KEY" \
  --from-literal=LLM_BASE_URL="https://maas-rhdp.apps.maas.redhatworkshops.io/v1"

oc annotate secret continue-llm-credentials \
  -n openshift-devspaces \
  controller.devfile.io/mount-as=env

oc label secret continue-llm-credentials \
  -n openshift-devspaces \
  app.kubernetes.io/part-of=che.eclipse.org \
  app.kubernetes.io/component=workspaces-config

echo "LLM credentials secret created successfully"
After the secret has been created, every newly created workspace automatically receives the following environment variables: LLM_API_KEY, LLM_BASE_URL
Later in this training, you’ll create a Devfile that uses these environment variables to automatically configure AI coding assistants such as Continue.
