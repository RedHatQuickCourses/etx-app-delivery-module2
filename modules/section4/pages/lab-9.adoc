= Lab 9: Configure GitLab Integration and Shared Secrets
:navtitle: Lab 9: GitLab Integration and Shared Secrets

In this lab, you'll integrate Red Hat Dev Spaces with GitLab using OAuth and configure shared secrets that are automatically available to developer workspaces.

GitLab integration enables developers to clone, pull, and push repositories without manually configuring Git credentials. You'll also configure shared workspace secrets that can be used to provide common configuration, API keys, and service credentials to every workspace.

By the end of this lab, you will have:

* Configured GitLab OAuth integration for Red Hat Dev Spaces
* Registered GitLab as a source code management provider
* Created shared secrets for developer workspaces
* Learned how Dev Spaces automatically injects shared configuration into workspaces

== Configure GitLab OAuth Integration

Red Hat Dev Spaces integrates with GitLab using OAuth. Once configured, users authenticate with their GitLab account and can access repositories directly from their workspaces.

== Configure GitLab Authentication

Create a Kubernetes Secret that stores the GitLab OAuth credentials. Red Hat Dev Spaces automatically discovers this secret based on its labels and annotations.

WARNING: Replace `GITLAB_APPLICATION_ID` and `GITLAB_APPLICATION_SECRET` with the values generated by GitLab before running the following commands.

[source,bash,role=execute]
----
# Get the GitLab URL dynamically from the cluster
GITLAB_URL="https://$(oc get route -n gitlab -l app=webservice -o jsonpath='{.items[0].spec.host}')"

echo "Using GitLab URL: $GITLAB_URL"

oc create secret generic gitlab-oauth-config \
  -n openshift-devspaces \
  --from-literal=id="$GITLAB_APPLICATION_ID" \
  --from-literal=secret="$GITLAB_APPLICATION_SECRET"

oc annotate secret gitlab-oauth-config \
  -n openshift-devspaces \
  che.eclipse.org/oauth-scm-server=gitlab \
  che.eclipse.org/scm-server-endpoint="$GITLAB_URL"

oc label secret gitlab-oauth-config \
  -n openshift-devspaces \
  app.kubernetes.io/part-of=che.eclipse.org \
  app.kubernetes.io/component=oauth-scm-configuration

echo "GitLab OAuth secret created successfully"
----

Next, register GitLab with the Dev Spaces `CheCluster`.

[source,bash,role=execute]
----
# Get the GitLab URL dynamically from the cluster
GITLAB_URL="https://$(oc get route -n gitlab -l app=webservice -o jsonpath='{.items[0].spec.host}')"

echo "Registering GitLab URL: $GITLAB_URL"

oc patch checluster devspaces -n openshift-devspaces \
  --type='merge' \
  -p "{\"spec\":{\"gitServices\":{\"gitlab\":[{\"secretName\":\"gitlab-oauth-config\",\"endpoint\":\"$GITLAB_URL\"}]}}}"
----

NOTE: After GitLab is registered, users are prompted to authorize Dev Spaces the first time they open a workspace that references a GitLab repository. Once authorized, Git operations such as clone, pull, and push use the user's GitLab identity automatically.

== Configure Shared Workspace Secrets

Red Hat Dev Spaces can automatically mount Kubernetes Secrets and ConfigMaps into every workspace. This allows administrators to provide shared configuration, credentials, or API keys without requiring developers to configure them manually.

Secrets can be injected in one of the following ways:

* **Environment variables** (`mount-as: env`)
* **Files** (`mount-as: file`)
* **Individual files using subpaths** (`mount-as: subpath`)

== Example: Configure AI Coding Assistant Credentials

This example configures shared credentials for an AI coding assistant such as Continue, Roo, or Cline.

Begin by obtaining an API key from the Red Hat Demo Platform MaaS service.

. Open the MaaS portal.
+
image::maas_login.png[width=500]
+
. Sign in using your Red Hat Demo Platform credentials.
. Subscribe to the `qwen3-14b` model if you haven't already.
+
image::maas_sub.png[width=500]
+
. Navigate to *API Keys*.
. Create a new API key or select an existing one.
. Copy the generated API key.

Create the shared secret.

WARNING: Replace `REPLACE_API_KEY` with your MaaS API key before running the command.

[source,bash,role=execute]
----
oc create secret generic continue-llm-credentials \
  -n openshift-devspaces \
  --from-literal=LLM_API_KEY="REPLACE_API_KEY" \
  --from-literal=LLM_BASE_URL="https://maas-rhdp.apps.maas.redhatworkshops.io/v1"

oc annotate secret continue-llm-credentials \
  -n openshift-devspaces \
  controller.devfile.io/mount-as=env

oc label secret continue-llm-credentials \
  -n openshift-devspaces \
  app.kubernetes.io/part-of=che.eclipse.org \
  app.kubernetes.io/component=workspaces-config

echo "LLM credentials secret created successfully"
----

== Verify the Shared Secret Configuration

After the secret has been created, every newly created workspace automatically receives the following environment variables:

* `LLM_API_KEY`
* `LLM_BASE_URL`

NOTE: Later in this training, you'll create a Devfile that uses these environment variables to automatically configure AI coding assistants such as Continue.
